# ILAIOS Desktop — Microsoft Store submission checklist

This file records only externally required Store inputs. It does not assert that any account, identity, certification, or approval already exists.

## Deterministic repository/CI work

- Windows release build: automated.
- MSIX packaging: automated.
- Package structure inspection: automated.
- Canonical ILAIOS app branding: enforced from repository authority.
- Package checksum: generated by packaging script.
- Signing step: intentionally blocked until a trusted publisher identity is provisioned.

## External account/identity inputs required before public submission

- Active Windows app developer account in Microsoft Partner Center.
- Reserved Store product/app name.
- Partner Center package Identity Name.
- Partner Center Publisher identity string.
- First Store submission created manually when required by the applicable submission API workflow.
- Required age-rating questionnaire and Store declarations completed.
- Listing metadata, screenshots/assets, privacy/support information, markets and pricing/availability decisions supplied.

## Signing

For direct/non-Store trusted distribution, a valid code-signing certificate/private-key path is required. Secrets must be stored only in an approved secret store and injected at release time.

For Store distribution, package identity and publisher values must match the values assigned by Partner Center. CI must not guess them.

## Automation boundary

Once the Partner Center product exists and the required Entra/Partner Center authentication is deliberately provisioned, later submission operations may be automated through Microsoft's Store submission APIs where supported. Account creation, app reservation, required first-submission steps, identity verification, payment and human declarations remain external human/account actions.
