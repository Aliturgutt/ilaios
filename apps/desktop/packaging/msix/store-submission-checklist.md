# ILAIOS Desktop — Microsoft Store submission checklist

This file records only externally required Store inputs and deterministic readiness work. It does not assert that any account, identity, certification, approval, policy answer, or publisher credential already exists.

## Deterministic repository/CI work

- Windows release build: automated.
- MSIX packaging: automated.
- Package structure inspection: automated.
- Canonical ILAIOS app branding: enforced from repository authority.
- Package checksum: generated by packaging script.
- Signing step: intentionally blocked until a trusted publisher identity is provisioned.
- Store listing draft: prepared in `store-listing-draft.md`; factual claims must remain limited to verified Desktop behavior.
- Restricted-capability justification: prepared in `run-full-trust-rationale.md`; Partner Center approval is not assumed.

## External account/identity inputs required before public submission

- Active Windows app developer account in Microsoft Partner Center.
- Reserved Store product/app name.
- Partner Center package Identity Name.
- Partner Center Publisher identity string.
- Store submission created in Partner Center or through a deliberately provisioned supported submission API path.
- Required age-rating questionnaire and Store declarations completed by an authorized human/account holder.
- Markets and pricing/availability decisions supplied.

## Store listing inputs

At least one Store listing language must be completed. Before submission, provide:

- A factual product description.
- At least one real screenshot of the shipping Desktop application. Repository or generated mockups must not be represented as product screenshots.
- Support contact/information required by Partner Center.
- Privacy-policy answer and policy URL/text when applicable to the app's actual data handling and declared capabilities.
- Optional feature text, additional screenshots, and other merchandising assets only when they accurately reflect the released product.

## Restricted capability

The MSIX manifest currently declares `runFullTrust` because the packaged Flutter Windows executable is a classic desktop process using `Windows.FullTrustApplication`. Microsoft Store treats restricted capabilities as reviewable declarations. The submission must include a truthful explanation of why `runFullTrust` is necessary and how it is used; approval must not be presumed. See `run-full-trust-rationale.md`.

## Signing

For direct/non-Store trusted distribution, a valid code-signing certificate/private-key path is required. Secrets must be stored only in an approved secret store and injected at release time.

For Store distribution, package identity and publisher values must match the values assigned by Partner Center. CI must not guess them.

## Automation boundary

Once the Partner Center product exists and the required Microsoft Entra/Partner Center authentication is deliberately provisioned, later submission operations may be automated where Microsoft's Store submission APIs support the chosen package workflow. Account creation, app reservation, identity verification, payment, signing-key provisioning, age-rating answers, restricted-capability declarations, privacy declarations, and final certification submission remain external human/account actions unless a verified supported API and explicit authorization exist.
